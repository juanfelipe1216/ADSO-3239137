# T-02: migración inicial en PostgreSQL

Fecha: 14 de noviembre de 2026. El bloque anterior T-01 se subió en `deb0a03` antes de comenzar esta migración.

## Evidencia ejecutada

- Compose creó un volumen nuevo propio del proyecto y levantó PostgreSQL 16. La API esperó a su healthcheck y ejecutó la migración.
- `docker compose --env-file .env -f infra/compose.yaml exec -T api composer test`: **11 pruebas, 80 aserciones aprobadas**, incluidas ocho pruebas nuevas de integración con PostgreSQL real.
- La inspección de `information_schema.columns` mostró seis tablas y 30 columnas de negocio, exactamente los campos del modelo; ninguna con DEFAULT.
- Se verificaron las cinco categorías y sus UUID, rango de disponibles, unicidad parcial de referencia activa, reutilización después de baja y FK de categoría.
- `php artisan migrate --force`, ejecutado por segunda vez dentro del contenedor: `Nothing to migrate`.
- `docker compose --env-file .env -f infra/compose.yaml ps`: API y base saludables.

La prueba inicial tenía un conteo manual incorrecto de 33 columnas. Se contrastó con el modelo y el esquema (30 columnas) y se reemplazó la comprobación por los nombres exactos por tabla. No se alteró el modelo para satisfacer ese conteo erróneo.

## Configuración y límites

La contraseña de PostgreSQL se generó localmente y está en `.env`, ignorado. El comando usa `--env-file .env` explícitamente porque el Compose está en `infra`. La imagen excluye archivos de entorno. El motor no expone un puerto en el host.

T-18 (CHECK de total positivo y rol) sigue pendiente, como en la secuencia de referencia. Los préstamos no están implementados y las restricciones de stock no sustituyen las pruebas de concurrencia. Las pruebas insertan registros sintéticos en transacciones que se revierten; no borran datos existentes ni reinician volúmenes.
