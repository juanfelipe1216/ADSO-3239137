# B05: servicios y almacenamiento de fotografías

Sesión del 17 de noviembre de 2026. Commit localizable con `git log --all --grep="feat(covers): validate and store equipment photos (T-08/T-15)"`.

Se añadieron servicios separados para subir, quitar y consultar fotografías. Subir/quitar exige admin antes de consultar el recurso. Consultar exige equipo activo y fotografía existente; la autenticación HTTP todavía corresponde a T-16. MIME y dimensiones se comprueban desde el contenido, sin confiar en extensión ni MIME aportado por el cliente. Se permiten JPEG/PNG de hasta 2.097.152 bytes; no se realiza una recodificación ni un análisis antimalware.

El puerto `CoverStorage` mantiene separada la aplicación del disco. El adaptador local usa claves aleatorias hexadecimales de 64 caracteres, escritura exclusiva y rechazo de rutas o enlaces simbólicos. El proveedor es el punto de composición. Compose conserva las imágenes en un volumen privado `covers`, fuera de public; PHP permite transporte de 3 MiB por archivo y 8 MiB de petición para que el límite funcional pueda validarse en aplicación.

El guardado del equipo exige su versión vigente. Si pierde una subida, se elimina únicamente su archivo nuevo. Tras guardar correctamente una sustitución se elimina la imagen anterior. Quitar una foto guarda primero null y luego elimina el archivo; si ya no hay foto es idempotente. El adaptador de persistencia futuro debe completar/confirmar save antes de devolver, sin envolver estos servicios en una transacción externa que pueda deshacerse después de eliminar archivos. Fallos de disco durante limpieza se propagan; no existe todavía reparación automática de archivos huérfanos ante caídas del proceso.

