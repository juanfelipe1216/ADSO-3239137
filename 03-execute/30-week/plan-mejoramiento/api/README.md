# API Laravel

Estado del 18 de noviembre: Laravel arranca, la migración inicial está verificada y existen objetos de valor y dominio de equipos, préstamos, investigadores y usuarios (T-01 a T-06). T-12 incorpora repositorios y lectores PostgreSQL de usuarios, investigadores y catálogo. `composer.json`, `composer.lock`, `artisan` y `tests` están directamente en esta carpeta. Las operaciones de negocio por HTTP siguen pendientes.

Responsabilidades: las 21 operaciones de [contrato](../docs/api-contract.md), reglas del laboratorio, seguridad, transacciones y adaptadores. [Arquitectura](../docs/architecture.md) define las dependencias; [tareas](../docs/tasks.md) T-01 a T-19 definen su evidencia.

No conservar migraciones de ejemplo para usuarios con email, caché, colas, sesiones o reset de contraseñas. Las seis tablas del negocio se crean exclusivamente por migración en `lab_equipment`; la contabilidad de migraciones Laravel queda fuera. El admin se aprovisiona con valores de entorno, nunca con un password publicado.

T-07 implementa `LoginService` y `CreateLabTechnicianService` con puertos propios y fakes reutilizables. Se verifica autorización admin, rol de alta limitado a laboratorista, normalización, contraseña de 12-128 caracteres y duplicados, sin Laravel ni base de datos en esas pruebas. Los adaptadores reales de hash, JWT y repositorio de usuarios ya están verificados y compuestos; conexión HTTP pendiente: no hay aún login operativo en la API.

Desde la raíz del proyecto: `docker compose --env-file .env -f infra/compose.yaml up --build -d` y `docker compose --env-file .env -f infra/compose.yaml exec -T api composer test`. El segundo comando ejecuta actualmente 287 casos y 1.058 aserciones, en treinta y dos archivos de pruebas; el mínimo numérico se alcanza, pero el contrato HTTP completo y la concurrencia de préstamos siguen pendientes.

T-08 incorpora el alta de investigadores con documento único, validaciones sin efectos parciales y pruebas con fakes. También están probadas las consultas de investigadores con filtros, paginación y conteo de líneas pendientes. También se verificaron los servicios de catálogo con roles, búsquedas, stock y versión interna. Fotografías y almacenamiento local están verificados desde el 17. T-12 prueba contratos compartidos de repositorios y lectores contra PostgreSQL real, incluidos duplicados, baja lógica, referencia reutilizable tras baja y rechazo de una versión anterior después de otra escritura confirmada. Siguen pendientes persistencia de préstamos y conexión HTTP.

T-09 incorpora `LendEquipmentService`, `LoanRepository` y `TransactionManager`, probados sin Laravel ni base de datos. Se valida una o dos líneas, duplicados, existencia, vencidos, máximo acumulado de dos pendientes y stock. El préstamo usa el operador autenticado, un único instante de Clock y datos congelados. El fake transaccional revierte stock y préstamos ante errores, incluso después de una escritura. Los adaptadores reales de estos dos puertos y su composición quedan pendientes de T-13/T-17; no se conecta un fake a producción.

T-10 está verificada con fakes: la devolución relee el préstamo bajo el bloqueo del investigador, comprueba pertenencia y devolución única, registra la fecha de Clock y restituye una unidad de manera atómica. Los errores de escritura revierten la devolución; el histórico se conserva. `ListOverdueService` usa un único instante UTC para seleccionar líneas pendientes vencidas y calcular días completos; el orden es vencimiento e id. Se probó el límite estricto, fracciones de segundo, cambios de zona y desaparición de líneas tras devolverlas. Los lectores PostgreSQL y HTTP siguen pendientes.

T-11 tiene probados `MostBorrowedReportService` y `PostgresReportReader`: autoriza solo al administrador antes de validar fechas o consultar, aplica un rango de días UTC inclusivo y devuelve únicamente los cuatro campos agregados del contrato. Las devoluciones no reducen el conteo y los cambios de nombre/categoría crean grupos históricos distintos. El lector agrupa en SQL sin unir el catálogo; los contratos contra fake y PostgreSQL comprueban que renombrar, recategorizar y retirar equipos conserva el histórico. La composición está en `LabServiceProvider`; HTTP sigue pendiente.
